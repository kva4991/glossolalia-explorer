# Проверка проекта и документации

## Окружение и рабочий каталог

Команды ниже запускаются из корня клона Glossolalia Explorer в PowerShell. На компьютере разработчика это `C:\Users\User\Documents\Глоссариа\project`; в другом клоне используйте его корень.

Для документации нужны Git и PowerShell 5.1 или 7. Python, FFmpeg и модель не используются. Проверяются только файлы, видимые Git; локальные записи и результаты из исключённых каталогов не сканируются. Корневой `.aiignore`, если он есть, применяется как дополнительный список исключений в синтаксисе Git.

## Аудит документации

После изменения реестра пересоберите только карту:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Sync-Documentation.ps1 -Write
```

Команда читает реестр и Markdown, проверяет их и обновляет только `docs/dev/tag-map.md`. Для отмены генерации восстановите прежнюю карту из своей контрольной копии или Git после просмотра diff.

Проверка без записи:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Sync-Documentation.ps1
pwsh -NoProfile -File .\scripts\Sync-Documentation.ps1
git diff --check
```

Успех — код 0 и сообщение `Documentation OK` со счётчиками; у `git diff --check` нет вывода. Ошибка аудита завершает процесс ненулевым кодом. При устаревшей карте сначала обновите реестр, затем выполните вариант с `-Write`. Не используйте `-Write` для сокрытия ошибки ссылки или неизвестной метки.

Проверяются полнота реестра, уникальность путей и меток, статусы, соответствие H1 названию, уровни заголовков, закрытие блоков кода, подписи изображений, относительные Markdown-ссылки и их якоря, определения ссылок и актуальность карты. Обычные ссылки и ссылки через именованные определения поддерживаются; произвольный HTML не является форматом навигации проекта.

Аудитор не обращается к сети, не выполняет команды из Markdown и не доказывает истинность текста, качество распознавания или работу Android.

## Регрессионная проверка аудитора

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Documentation.ps1
pwsh -NoProfile -File .\tests\Test-Documentation.ps1
```

Успех — код 0 и `Documentation regression tests OK`. Тест создаёт небольшой Git-репозиторий во временной папке, проверяет корректные документы и намеренные повреждения, затем удаляет только свою папку. Рабочий проект, его индекс Git и пользовательские данные не меняются. Если Git отсутствует в PATH, сначала установите его или откройте консоль с доступным Git.

## Поведение Windows-скрипта

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Project.ps1
pwsh -NoProfile -File .\tests\Test-Project.ps1
```

Успех — код 0 и JSON с `Passed: true`. Тест использует управляемые ответы внешних команд, создаёт синтетические файлы во временной папке и не требует скачивания модели. Проверяет прямой запуск через `-File` с отсутствующим Python, очередь, имена, ошибки и маркировку профилей; не проверяет реальное распознавание и ручной диалог выбора. Текущая версия этого теста оставляет свою временную папку для разбора.

Для реального движка используйте [Smoke-Allosaurus](../tests/Smoke-Allosaurus.ps1) при установленных Allosaurus и FFmpeg:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Smoke-Allosaurus.ps1
```

Он создаёт синтетический WAV и отчёт во временной папке, запускает универсальный режим и пять пользовательских профилей. Успех подтверждает подключение и завершение этих режимов; точность языка не оценивается. Условия и параметры проверяйте в самом скрипте перед запуском.

## ZIPA и Wav2Vec2Phoneme

Из корня проекта в PowerShell, при установленном Python 3.12:

```powershell
py -3.12 -B -X utf8 .\tests\test_phonetic_engine.py
```

Семь тестов не требуют моделей или сторонних Python-пакетов. Проверяют CTC-повторы, обрезку перекрытий, Unicode в именах, коллизии TXT с сохранением старого содержимого, переиспользование WAV, ошибку конвертации, несовпадение ревизии и продолжение очереди после ошибки. Успех — код 0 и `OK`; синтетические файлы создаются и удаляются во временной папке.

После [установки](PHONETIC-ENGINES.md) проверьте реальные модели:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-ZIPA.ps1 -CheckOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-W2V2.ps1 -CheckOnly
pwsh -NoProfile -File .\Start-ZIPA.ps1 -CheckOnly
pwsh -NoProfile -File .\Start-W2V2.ps1 -CheckOnly
```

Успех — «Проверка пройдена» и код 0. Команды загружают локальные модели и выполняют расчёт на синтетическом сигнале; TXT не создаются. Для проверки очереди укажите реальные пути через `-AudioPath` из PowerShell: новые TXT появятся рядом с аудио согласно правилам инструкции.

22.09.2026 обе модели прошли установку и пробный расчёт. На шести локальных записях созданы 12 отдельных TXT; SHA-256 исходных WAV до и после совпали. В этом прогоне ZIPA запускалась через PowerShell 5.1, W2V2 — через PowerShell 7. Дополнительно на синтетическом M4A в PowerShell 5.1 проверены конвертация, продолжение после повреждённого WAV, повторное использование WAV и сохранение нового TXT при коллизии; ZIPA также прошла CheckOnly в PowerShell 7. Ручной диалог выбора и лингвистическая точность отдельно не проверены; полные результаты в Git не включены.

## Поиск повторяющихся сочетаний

Из корня проекта в PowerShell 5.1 или 7, с установленным Python 3.12 (путь ниже соответствует компьютеру автора):

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B -X utf8 .\tests\test_repeat_index.py
```

Девять тестов стандартной библиотеки проверяют исключение результатов с ограничивающим профилем, а также исключение повторных запусков и побайтовых копий, выбор даты с часовым поясом, разделение моделей и ревизий, неперекрывающиеся вхождения, границы окон/маркеров/блоков, сохранение фонетических различий, повреждённый отчёт, отсутствующий WAV и создание результата без перезаписи. Успех — код 0 и `OK`. Синтетические файлы создаются и удаляются во временной папке; модели и сеть не используются. Это проверка подсчёта, а не значения сочетаний.

Команда для реальных отчётов и её ограничения находятся в [словаре](LEXICON.md). 22.09.2026 проверены шесть исходных WAV и 18 отчётов: 331 точный повтор длиной 4–8 меток, из них 238 между записями. Отобранные карточки сверены с позициями в исходных TXT; независимое прослушивание не выполнено.

## Три модели и паузы

Из корня проекта в PowerShell, Python 3.12 без моделей:

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B -X utf8 .\tests\test_pause_tools.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-ThreeModels.ps1 -PythonPath "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
pwsh -NoProfile -File .\tests\Test-ThreeModels.ps1 -PythonPath "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
```

Восемь Python-сценариев проверяют границы трёх классов, переходы речевой активности, начальную/конечную паузы, неполный последний кадр, некорректные вероятности, сохранность фонетических меток, временные ориентиры CTC, пустой отчёт и запрет сочетаний через паузу. PowerShell-тест проверяет запуск оставшихся моделей после ошибки первой, устранение повторных путей и сохранность исходника. Он использует временный Python-обработчик, не загружает модели и оставляет свою временную папку для разбора. Успех — `OK` / `Three-model tests OK` и код 0; сообщение Expected test failure ожидается внутри проверки.

Для реальных моделей после [установки пауз](PAUSES.md):

```powershell
.\Start-AllModels.ps1 -CheckOnly
```

Успех подтверждает расчёт всех трёх моделей и VAD на синтетическом сигнале, не точность распознавания. При изменении разметки дополнительно проверьте запись с известными вставленными остановками и сравните три результата. Сверьте фонемы в аннотированной и исходной последовательностях, интервалы пауз, правило _NEW и SHA-256 исходников.

22.09.2026 общий CheckOnly прошёл в PowerShell 5.1. Контрольная запись с вставленными остановками 0,4 / 0,96 / 2,0 с дала интервалы VAD длиной 0,384 / 0,960 / 2,016 с и все три ожидаемых класса. Для неё созданы три реальных TXT; интервалы совпали, фонетические метки сохранены. На шести пользовательских WAV общий запуск в PowerShell 7 создал 18 TXT формата 2; проверены одинаковые интервалы, сохранность меток и чтение словарным парсером. SHA-256 всех шести WAV совпали с исходными. Независимое прослушивание и ручной диалог выбора не проверены; сохранность прежних TXT этим прогоном не подтверждена, поскольку они отсутствовали при новом создании.

## Экспериментальный язык для трёх моделей

В корне проекта, PowerShell 5.1/7, установленный Python 3.12:

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B -X utf8 .\tests\test_language_profiles.py
.\Start-AllModels.ps1 -Profile author-semitic -CheckOnly
```

Восемь новых тестов стандартной библиотеки проверяют структуру профиля, составные представления, явные варианты записи, CTC-пустоту, маску перед выбором метки, отказ при пустом пересечении, сохранность обычных TXT и сведения о профиле в отчёте. Модели не загружаются, синтетические файлы создаются во временной папке. Успех — `OK` и код 0. `Test-ThreeModels.ps1` дополнительно проверяет передачу `-Profile` всем трём движкам при ошибке одного из них.

CheckOnly использует реальные установленные модели, синтетический сигнал и локальный VAD; пользовательские TXT не создаёт. 23.09.2026 профиль прошёл эту проверку в Windows PowerShell 5.1. Доступно представлений из 52: Allosaurus — 47, ZIPA — 52 с раздельными метками, W2V2 — 49. Это совместимость набора и исполнения, не оценка языковой точности.

После изменения маски нужно проверить реальную запись, наличие только разрешённых меток, совпадение VAD-интервалов с обычным запуском, сохранность прежних TXT и SHA-256 аудио. Устройство и ограничения — [LANGUAGE-PROFILES](LANGUAGE-PROFILES.md).

## CI и результаты

[GitHub Actions](../.github/workflows/checks.yml) запускает аудит, регрессионные сценарии аудитора, пакетные проверки и очередь трёх моделей в PowerShell 5.1 и 7. Python 3.12 дополнительно проверяет общий обработчик движков, поиск повторов и паузы без весов моделей. Интеграционные тесты с моделями запускаются отдельно.

[VALIDATION](VALIDATION.md) фиксирует результаты конкретной версии и незакрытые проверки. Для нового отчёта указывайте дату, окружение, команды, результат и ограничения; не заменяйте ручную проверку устройства зелёным CI.

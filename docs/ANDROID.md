# Android-приложение Glossolalia Explorer

Статус: запланировано. Этот документ описывает будущую реализацию. Android-модуля и APK в текущей версии проекта ещё нет; работающий распознаватель сейчас запускается через PowerShell на компьютере.

[Авторская теория «протокола»](THEORY.md), уточнённая до версии 2.0, предлагает отдельные принципы: экран исповедания, «ОК» как религиозный образ согласия и отказ показывать ненадёжную расшифровку. Эти предложения не включены в данный план и не меняют описанный ниже способ показа фонетического результата и передачи текста.

## Результат для пользователя

Приложение записывает звук как диктофон, получает фонетическую расшифровку, добавляет подходящий промпт и передаёт подготовленный текст во внешнее приложение нейросети на телефоне.

Согласован способ работы с чатом: системное действие **«Поделиться»** с выбором отдельного приложения ChatGPT, Gemini или другого совместимого получателя. Встроенный чат через API в эту постановку не входит.

```mermaid
flowchart LR
    A["Запись на телефоне"] --> B["Фонетическое распознавание"]
    B --> C["Просмотр результата"]
    C --> D["Промпт + расшифровка"]
    D --> E["Поделиться → приложение нейросети"]
```

## Пользовательский сценарий

1. Пользователь начинает запись, при первом обращении предоставляет доступ к микрофону, затем останавливает запись.
2. Запись сохраняется на телефоне; доступны имя, длительность и прослушивание. Завершённая запись остаётся доступной после закрытия приложения.
3. Пользователь запускает фонетическое распознавание и видит состояние обработки. Ошибка не удаляет запись и допускает повторную попытку.
4. Результат содержит универсальную IPA-транскрипцию и выбранные дополнительные профили, приблизительные таймстампы, доступные альтернативы и оценки модели.
5. Приложение подставляет результат в версионируемый шаблон промпта. Для речи и пения используются соответствующие указания; если тип неизвестен, смысл и тип записи не угадываются автоматически.
6. Пользователь просматривает готовое сообщение, при необходимости уточняет контекст, затем нажимает «Поделиться» и выбирает установленное приложение нейросети.
7. Дальнейшую отправку сообщения и работу с ответом выполняет приложение-получатель. Наше приложение не объявляет сообщение отправленным только потому, что открылось меню обмена.

Полные записи и расшифровки остаются личными данными и не попадают в Git. Передача подготовленного текста в выбранное приложение — явное действие пользователя. В обычный пакет обмена входит текст, без автоматического прикрепления аудио.

## Диктофон и обработка

- Использовать Android API записи звука и запрашивать разрешение RECORD_AUDIO.
- Для сценария записи при погашенном экране или переходе в другое приложение использовать foreground service с типом microphone и необходимыми разрешениями. Начинать запись из видимого интерфейса, отображать уведомление с состоянием записи.
- До подачи в текущую модель приводить рабочую копию к формату mono, 16 кГц, PCM 16 bit; сохранять исходную запись.
- Получать именно фонетическую транскрипцию. Обычный сервис распознавания слов или автоматическая транслитерация готового текста не заменяют этот этап.
- Сохранять отметки экспериментальности профилей и сведения о неподдерживаемых символах. Оценки модели не выдавать за вероятность языка или правильность перевода.
- Не смешивать исходный результат распознавателя с исправлениями и предположениями пользователя.

Место выполнения распознавания ещё не выбрано: на телефоне либо на компьютере/сервере. Подготовка диктофона, экрана результата и сборки сообщения не должна скрывать этот нерешённый вопрос.

## Передача во внешний чат

Использовать Android Sharesheet: Intent.ACTION_SEND, MIME text/plain, подготовленное сообщение в Intent.EXTRA_TEXT, выбор получателя через Intent.createChooser.

Передавать промпт и транскрипцию одним текстом в определённом порядке. Это пользовательское сообщение для внешнего чата; у нашего приложения нет гарантированной возможности установить системный промпт, выбрать конкретный разговор или нажать «Отправить» в чужом приложении.

Совместимость ChatGPT/Gemini с приёмом такого текста необходимо проверить на реальных устройствах и установленных версиях. Если подходящего приложения нет в меню или оно не принимает текст, предоставить «Копировать промпт и расшифровку» для ручной вставки. При слишком большом объёме не обрезать результат молча: предложить выбрать временной фрагмент и явно указать его границы.

Отмена выбора получателя сохраняет подготовленное сообщение и запись.

## Подходящий промпт

Планируется версионируемый шаблон промпта, который приложение заполняет результатами распознавания. Текст шаблона и его сборщик будут подготовлены на этапе реализации.

В сообщение подставляются:

- версия шаблона, обозначение записи, тип и дополнительный контекст, заданные пользователем;
- модель и режимы распознавания, предупреждения об ограничениях;
- исходная фонетическая транскрипция выбранного участка;
- указание отделять наблюдаемые звуки от языковых гипотез, переводов и личных толкований.

Формулировки для пения учитывают растягивание гласных и нестабильность сегментации. Религиозный контекст указывается только со слов пользователя. Личные гипотезы из справочного документа не подставляются в промпт как доказанные факты; примеры из литературы не служат заранее правильными ответами.

## Основа реализации

Существующая основа: Start-Glossolalia.ps1, languages.json, пять файлов профилей и docs/METHODOLOGY.md. Их поведение задаёт содержание результата, но Windows-скрипт сам по себе не является Android-движком.

После выбора места обработки:

- Для компьютера/сервера определить транспорт, адрес подключения, формат задания и ответа, состояние задачи и правила хранения переданного аудио.
- Для телефона сначала проверить перенос акустической модели и подготовки признаков, совместимость выходных символов, время обработки, память и расход батареи. Автономное распознавание не считать готовым до этой проверки.

Не вводить обязательный сервер или конкретный мобильный runtime до выбора варианта.

## Этапы реализации

1. **Выбрать место распознавания.** Сопоставить обработку на телефоне и на компьютере/сервере; проверить выбранный вариант на короткой тестовой записи. Результат этапа — подтверждённый способ получения IPA и список ограничений.
2. **Сделать диктофон.** Запись, остановка, локальное сохранение и прослушивание; обработка разрешений и жизненного цикла записи.
3. **Подключить фонетическое распознавание.** Передать запись выбранному движку, показать ход работы, сохранить результат и ограничения профилей, обеспечить повтор после ошибки.
4. **Подготовить сообщение для нейросети.** Создать шаблон промпта, подставлять тип записи и фонетические данные, показывать пользователю итоговый текст.
5. **Добавить передачу через «Поделиться».** Проверить получение текста внешними приложениями; предусмотреть копирование и отмену без потери данных.
6. **Проверить полный сценарий на телефоне.** От записи до готового текста в выбранном приложении нейросети, включая длинные записи, ошибки и неподдерживаемые получатели.

Сроки и оценка трудоёмкости определяются после первого этапа: перенос фонетического движка на телефон и серверный вариант требуют разного объёма работ.

## Приёмка

- Отказ в доступе к микрофону объясняется пользователю; приложение не падает.
- Запись можно завершить и прослушать; при смене экрана она обрабатывается согласно выбранному сценарию диктофона.
- Распознанные IPA-символы, включая диакритику, сохраняются без замены и повреждения.
- Ошибки одного профиля видны отдельно, доступные результаты сохраняются.
- В сообщении есть промпт, исходная транскрипция, модель и маркировка неофициальных профилей.
- Речь, пение и неопределённый тип дают согласованные варианты инструкций без выдуманного контекста.
- «Поделиться» передаёт полный выбранный текст; отмена не теряет данные.
- Копирование даёт тот же текст, что и передача через Sharesheet.
- При недоступном получателе или слишком большом объёме есть понятный выход без молчаливой потери текста.

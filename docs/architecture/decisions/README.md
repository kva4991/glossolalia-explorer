# Архитектурные решения

ADR (Architecture Decision Record) хранит причину устойчивого выбора. Подробное текущее поведение остаётся в тематическом документе.

| Решение | Статус решения | Состояние реализации |
| --- | --- | --- |
| [0001: границы фонетического исследования](0001-phonetic-boundary.md) | Принято | Действующие правила Windows-версии и методики |
| [0002: внешний чат Android](0002-android-sharing.md) | Принято | Только план приложения |
| [0003: система документации](0003-documentation-system.md) | Принято | Реестр, карта и аудит документации |
| [0004: отдельные движки](0004-phonetic-engines.md) | Принято | ZIPA и Wav2Vec2Phoneme: локальные окружения, отдельные TXT |

## Порядок работы

Новый ADR создаётся по [шаблону](template.md) со следующим свободным номером. Допустимые статусы: «Предложено», «Принято», «Отклонено» и «Заменено ADR-NNNN».

Новое решение, меняющее принятое, получает новый номер; старый документ сохраняет контекст и ссылку на замену. Исправление опечатки не требует нового ADR. Одновременно обновляются индекс, реестр, тематические документы и проверки из [матрицы](../../CHANGE_IMPACT.md).

Не оформляйте неизвестный выбор как принятое решение. Например, место Android-распознавания остаётся открытым.

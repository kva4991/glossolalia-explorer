# Glossolalia Explorer

Автор проекта исследует, можно ли различить устойчивые звуковые сочетания в собственных записях молитвы на иных языках и проверить предположения об их смысле. Слова возникали без заранее подготовленного текста. Распознавание даёт фонетические метки для сравнения, но само по себе не определяет язык, перевод или духовное происхождение молитвы.

Рабочий путь: сохранить исходную запись и условия записи; получить отдельные результаты трёх движков и разметку пауз; сверить звуки с аудио; отделить возможные словарные параллели от личного прочтения; повторить проверку на новых записях и контрольном материале. Подробности и ограничения — в [методике](docs/METHODOLOGY.md). Исходные аудио и машинные отчёты остаются локально; ручные транскрипции и варианты перевода публикуются по разрешению автора.

## Текущее состояние

- [Словарь](docs/LEXICON.md) содержит 9 карточек GLO с поиском повторов и отдельные серии текстовых кандидатов B2 (22), RUVI (51) и B3 (18). Последние три серии нельзя считать подсчитанными машиной повторами в аудио.
- [Типология обращений, «ключей» и описаний](docs/GLOSSOLALIA_AS_KEY.md) предложена для ручного разбора B3; [ADR-0008](docs/architecture/decisions/0008-glossolalia-units.md) имеет статус «Предложено».
- [Понятийный словарь](docs/TERMS.md) фиксирует авторские определения и их статус отдельно от фонетического словаря. [Религиозные источники](docs/BIBLICAL_CONTEXT.md) и [различение](docs/SPIRITUAL_DISCERNMENT.md) рассматриваются с указанием границ проверки.
- Версия для Windows запускает Allosaurus, ZIPA и Wav2Vec2Phoneme. Пять пользовательских профилей и профиль `author-semitic` — **экспериментальные, неофициальные**; они ограничивают набор выходных звуков, а не создают обученную модель языка.

## Инструменты для Windows

### Возможности Allosaurus

- Массовое выделение файлов через Ctrl/Shift или передача нескольких путей командой.
- 16 режимов: универсальный IPA, 10 встроенных языковых наборов и 5 пользовательских.
- Галилейский арамейский, мандейский арамейский, классический сирьяк, койне, латынь.
- Проверка доступности режимов и звуков до распознавания.
- Отдельная отметка **«ЭКСПЕРИМЕНТАЛЬНЫЙ, НЕОФИЦИАЛЬНЫЙ ПРОФИЛЬ»** в консоли и TXT.
- Повторное использование одноимённого WAV.
- Файл результата с исходным именем: `запись.txt`. При совпадении: `запись_NEW.txt`, затем `запись_NEW_NEW.txt`.
- Ошибка одного режима не останавливает остальные; ошибка конвертации не останавливает очередь.
- Большая зелёная галочка после сохранения TXT; отчёт автоматически не открывается.

### Три модели с паузами

Основной [Start.cmd](Start.cmd) или [Start-AllModels.cmd](Start-AllModels.cmd) создаёт три TXT на каждую выбранную запись: `(Allosaurus)`, `(ZIPA)` и `(W2V2)`. Внутри транскрипций отмечаются короткие, средние и длинные паузы, определённые общим локальным Silero VAD. Существующие файлы сохраняются; новые при совпадении получают `_NEW`.

После установки трёх движков выполните `Setup-Pauses.ps1`. [Инструкция пауз и общего запуска](docs/PAUSES.md) описывает пороги, расположение моделей, ошибки и ограничения. Allosaurus в этом сценарии использует универсальный IPA; прежние 16 профилей доступны отдельно.

### Авторский язык для трёх моделей

[Start-AuthorProfile.cmd](Start-AuthorProfile.cmd) запускает экспериментальный неофициальный профиль «Авторский семитский» (`author-semitic`). Он ограничивает фонетические метки трёх моделей до декодирования и создаёт отдельные результаты вида `1_author-semitic (ZIPA).txt`. Обычный запуск остаётся доступен для сравнения. [Инструкция и ограничения профиля](docs/LANGUAGE-PROFILES.md).

### ZIPA и Wav2Vec2Phoneme

Доступны два отдельных запуска: [Start-ZIPA.cmd](Start-ZIPA.cmd) и [Start-W2V2.cmd](Start-W2V2.cmd). Они поддерживают массовый выбор, сохраняют TXT с суффиксом модели и используют отдельные локальные окружения. Например: `4 (ZIPA).txt`, `4 (W2V2).txt`; при совпадении — `4_NEW (ZIPA).txt`.

[Инструкция установки двух движков](docs/PHONETIC-ENGINES.md) содержит выполненные шаги, закреплённые версии, команды и ограничения. Прежний запуск Allosaurus описан ниже.

## Требования и установка

Windows, PowerShell 5.1 или 7, Python 3.12, FFmpeg в PATH. Рабочая связка проверена с Allosaurus 1.0.2 и моделью uni2005. Другие версии Python не проверены.

```powershell
git clone https://github.com/kva4991/glossolalia-explorer.git
cd glossolalia-explorer
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Glossolalia.ps1 -CheckOnly
```

`Setup.ps1` создаёт локальное окружение `.venv`, устанавливает зависимости из PyPI и загружает модель uni2005 из источника Allosaurus. Нужны интернет и место для PyTorch и модели. FFmpeg установите отдельно из [официальных источников](https://ffmpeg.org/download.html), затем откройте новую консоль. Проверка доступности: `ffmpeg -version`.

При наличии своего Python можно выполнить `Setup.ps1 -PythonPath 'D:\Python312\python.exe'`. Политика выполнения в командах выше применяется только к запускаемому процессу.

Уже установленное окружение также подходит: передайте `-PythonPath`. Без параметра программа ищет сначала `.venv\Scripts\python.exe`, затем прежнее окружение `allosaurus-env` в домашнем каталоге пользователя.

## Запуск

Дважды щёлкните `Start.cmd` для трёх моделей с паузами. Окно останется открытым для чтения сообщений. По умолчанию выбор начинается в родительской папке проекта; в исходном расположении это папка `Глоссариа`. Следующие команды запускают прежний экспертный режим Allosaurus с 16 профилями:

В PowerShell:

```powershell
.\Start-Glossolalia.ps1
.\Start-Glossolalia.ps1 -InitialDirectory 'D:\Audio'
.\Start-Glossolalia.ps1 -AudioPath 'D:\Audio\1.m4a','D:\Audio\2.wav'
.\Start-Glossolalia.ps1 -AudioPath 'D:\Audio\1.wav' -Modes ipa,galilean,mandaic
.\Start-Glossolalia.ps1 -CheckOnly
```

Параметры `-PythonPath` и `-FfmpegPath` принимают пути к нужным исполняемым файлам. `-Model` выбирает уже установленную модель, по умолчанию `uni2005`. Неизвестный режим в `-Modes` считается ошибкой.

Рядом с `1.m4a` создаются `1.wav` (моно, 16 кГц, PCM 16 bit) и `1.txt`. Если WAV уже существует, он используется как есть. Для входного WAV рекомендуется такой же формат; программа не исправляет существующий WAV автоматически. Существующие TXT сохраняются.

Галочка означает сохранение отчёта. Состояние отдельных режимов и их ошибки указаны внутри; галочка не подтверждает точность распознавания.

## Профили и результаты

Настройки режимов находятся в [languages.json](languages.json), наборы звуков — в пяти TXT в корне проекта. Их текущий состав сохранён из пользовательских файлов. [Описание профилей](README-profiles.md) содержит число звуков, известные ограничения и происхождение.

Файлы WAV, аудиозаписи, результаты TXT и окружение Python исключены из Git. Автоматические отчёты в других форматах храните в `private/` или `results/`; разрешённые к публикации ручные транскрипции находятся в [литературе](docs/LITERATURE.md). Модели в репозиторий не включаются. Исключения для пяти профилей и `requirements.txt` заданы явно. Не используйте имена файлов профилей для аудиозаписей внутри корня проекта: одноимённый TXT уже занят.

Оценки `p` относятся к выходу модели в выбранном наборе, а не к вероятности языка. В прежнем экспертном режиме паузы обозначают промежутки между распознанными звуками; общий новый запуск использует [VAD по аудио](docs/PAUSES.md). Таймстампы приблизительны. Пустой результат сам по себе не доказывает тишину. См. [методику](docs/METHODOLOGY.md).

## Как передать документацию в другой чат

На GitHub можно скачать архив через `Code` → `Download ZIP`. Если чат с Алисой AI принимает ZIP и умеет открывать архивы, передайте его вместе с просьбой прочитать README и нужные документы. Если принимает только текстовые файлы, отправьте сами Markdown-файлы. Простое переименование `.zip` в `.txt` не превращает архив в текст и не гарантирует, что чат сможет его распаковать. Публичный репозиторий не содержит личных аудио и полных расшифровок.

## Разработка и проверка

Точные команды аудита документации и тестов, зависимости и границы проверки: [TESTING](docs/TESTING.md).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Project.ps1
pwsh -NoProfile -File .\tests\Test-Project.ps1
```

Проверки без Allosaurus используют управляемые ответы внешних команд: массовую обработку, ошибки, коллизии имён, маркировку профилей и top-3. GitHub Actions запускает их в обеих версиях PowerShell.

[Проверка реального распознавателя](tests/Smoke-Allosaurus.ps1) создаёт синтетический WAV во временной папке и запускает IPA и пять пользовательских режимов. Требует установленного Allosaurus и FFmpeg; это проверка подключения, не качества языка.
